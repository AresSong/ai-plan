Atomic work item connects intent to design, repository changes, code and tests

One allowed atomic work item—currently Story or Bug—may change several repositories. Each affected Repository has one work-item-linked Pull Request, and each production Pull Request implements exactly one atomic work item. Semantic recovery proposes missing links across work items, design, code and tests for review.

PR is the repository bridge

The AtomicWorkItem links to one Pull Request in each affected Repository. Each completed base-to-target comparison yields file and symbol changes; commit history stays inside the source platform rather than this system overview.

Semantic links require review

Dashed lines show semantic matching support, not accepted business links. Profiles contribute evidence to a proposed TraceLink; review can accept or reject it without replacing declared or deterministic evidence.

Component mapping is separate

A CodeSymbol IMPLEMENTS a Component. File, Module and Repository describe source location and must not assign the Component by themselves.
